I want to Create Docker compose file for our Spring Boot App , MYSQL And MongoDb So how to do it ?

Great choice! Running your Spring Boot app with MySQL and MongoDB together is a classic use case for Docker Compose. You’ll define each service (app, MySQL, MongoDB) in a docker-compose.yml file, and Compose will orchestrate them.

And docker-compose.yml

version: "3.9"

services:
  springboot-app:
    build: .
    container_name: springboot-app
    ports:
      - "8080:8080"
    environment:
      SPRING_DATASOURCE_URL: jdbc:mysql://db:3306/mydb
      SPRING_DATASOURCE_USERNAME: root
      SPRING_DATASOURCE_PASSWORD: root
      SPRING_DATA_MONGODB_URI: mongodb://mongo:27017/mydb
    depends_on:
      - db
      - mongo

  db:
    image: mysql:8
    container_name: mysql-db
    environment:
      MYSQL_ROOT_PASSWORD: root
      MYSQL_DATABASE: mydb
    ports:
      - "3306:3306"
    volumes:
      - mysql_data:/var/lib/mysql

  mongo:
    image: mongo:6
    container_name: mongo-db
    ports:
      - "27017:27017"
    volumes:
      - mongo_data:/data/db

volumes:
  mysql_data:
  mongo_data:


Steps to Run
Create a Dockerfile for your Spring Boot app (if not already done).

Place the above docker-compose.yml in your project root.

Run:
docker-compose up --build

Perfect — let’s design a production‑ready GitHub Actions pipeline for your Spring Boot app with MySQL and MongoDB, without relying on .env files. Instead, we’ll inject secrets directly from GitHub Actions into Docker Compose at runtime.

Workflow Overview
Build Spring Boot app image using your Dockerfile.

Push image to a container registry (Docker Hub or GitHub Container Registry).

Deploy with Docker Compose on your server, using GitHub Actions secrets for DB credentials.

Example GitHub Actions Workflow (.github/workflows/deploy.yml)

name: Deploy Spring Boot App

on:
  push:
    branches: [ "main" ]

jobs:
  build-and-deploy:
    runs-on: ubuntu-latest

    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Log in to Docker Hub
        uses: docker/login-action@v2
        with:
          username: ${{ secrets.DOCKER_USERNAME }}
          password: ${{ secrets.DOCKER_PASSWORD }}

      - name: Build Docker image
        run: |
          docker build -t ${{ secrets.DOCKER_USERNAME }}/springboot-app:latest .

      - name: Push Docker image
        run: |
          docker push ${{ secrets.DOCKER_USERNAME }}/springboot-app:latest

      - name: Deploy with Docker Compose
        run: |
          echo "version: '3.9'
          services:
            springboot-app:
              image: ${{ secrets.DOCKER_USERNAME }}/springboot-app:latest
              ports:
                - '8080:8080'
              environment:
                SPRING_DATASOURCE_URL: jdbc:mysql://db:3306/${{ secrets.MYSQL_DATABASE }}
                SPRING_DATASOURCE_USERNAME: root
                SPRING_DATASOURCE_PASSWORD: ${{ secrets.MYSQL_ROOT_PASSWORD }}
                SPRING_DATA_MONGODB_URI: mongodb://mongo:27017/${{ secrets.MONGO_DATABASE }}
              depends_on:
                - db
                - mongo
              restart: unless-stopped
              networks:
                - backend

            db:
              image: mysql:8
              environment:
                MYSQL_ROOT_PASSWORD: ${{ secrets.MYSQL_ROOT_PASSWORD }}
                MYSQL_DATABASE: ${{ secrets.MYSQL_DATABASE }}
              volumes:
                - mysql_data:/var/lib/mysql
              restart: unless-stopped
              networks:
                - backend

            mongo:
              image: mongo:6
              environment:
                MONGO_INITDB_DATABASE: ${{ secrets.MONGO_DATABASE }}
              volumes:
                - mongo_data:/data/db
              restart: unless-stopped
              networks:
                - backend

          volumes:
            mysql_data:
            mongo_data:

          networks:
            backend:
              driver: bridge" > docker-compose.prod.yml

          docker-compose -f docker-compose.prod.yml up -d

Would you like me to also show you how to extend this pipeline to deploy on a remote server via SSH (so GitHub Actions builds the image, pushes it, and then triggers deployment on your production host)?

Excellent — let’s extend your pipeline so GitHub Actions can deploy to a remote production server via SSH. This way, your workflow builds and pushes the Docker image, then securely connects to your server and runs docker-compose there.

Workflow with Remote Deployment
Here’s a production‑ready GitHub Actions workflow (.github/workflows/deploy.yml):

name: Deploy Spring Boot App

on:
  push:
    branches: [ "main" ]

jobs:
  build-and-deploy:
    runs-on: ubuntu-latest

    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Log in to Docker Hub
        uses: docker/login-action@v2
        with:
          username: ${{ secrets.DOCKER_USERNAME }}
          password: ${{ secrets.DOCKER_PASSWORD }}

      - name: Build Docker image
        run: |
          docker build -t ${{ secrets.DOCKER_USERNAME }}/springboot-app:latest .

      - name: Push Docker image
        run: |
          docker push ${{ secrets.DOCKER_USERNAME }}/springboot-app:latest

      - name: Deploy to Remote Server via SSH
        uses: appleboy/ssh-action@v0.1.10
        with:
          host: ${{ secrets.SERVER_HOST }}
          username: ${{ secrets.SERVER_USER }}
          key: ${{ secrets.SERVER_SSH_KEY }}
          script: |
            cd /home/${{ secrets.SERVER_USER }}/app
            echo "version: '3.9'
            services:
              springboot-app:
                image: ${{ secrets.DOCKER_USERNAME }}/springboot-app:latest
                ports:
                  - '8080:8080'
                environment:
                  SPRING_DATASOURCE_URL: jdbc:mysql://db:3306/${{ secrets.MYSQL_DATABASE }}
                  SPRING_DATASOURCE_USERNAME: root
                  SPRING_DATASOURCE_PASSWORD: ${{ secrets.MYSQL_ROOT_PASSWORD }}
                  SPRING_DATA_MONGODB_URI: mongodb://mongo:27017/${{ secrets.MONGO_DATABASE }}
                depends_on:
                  - db
                  - mongo
                restart: unless-stopped
                networks:
                  - backend

              db:
                image: mysql:8
                environment:
                  MYSQL_ROOT_PASSWORD: ${{ secrets.MYSQL_ROOT_PASSWORD }}
                  MYSQL_DATABASE: ${{ secrets.MYSQL_DATABASE }}
                volumes:
                  - mysql_data:/var/lib/mysql
                restart: unless-stopped
                networks:
                  - backend

              mongo:
                image: mongo:6
                environment:
                  MONGO_INITDB_DATABASE: ${{ secrets.MONGO_DATABASE }}
                volumes:
                  - mongo_data:/data/db
                restart: unless-stopped
                networks:
                  - backend

            volumes:
              mysql_data:
              mongo_data:

            networks:
              backend:
                driver: bridge" > docker-compose.prod.yml

            docker-compose -f docker-compose.prod.yml pull
            docker-compose -f docker-compose.prod.yml up -d



Key Points
Secrets in GitHub Actions:

DOCKER_USERNAME, DOCKER_PASSWORD → for Docker Hub login.

SERVER_HOST, SERVER_USER, SERVER_SSH_KEY → for SSH access.

MYSQL_ROOT_PASSWORD, MYSQL_DATABASE, MONGO_DATABASE → DB credentials.

appleboy/ssh-action → runs commands on your remote server via SSH.

Dynamic Compose file → generated on the server with secrets injected at runtime.

Pull latest image → ensures the server runs the newest build.

Restart policies → keeps services alive if they crash.


Deployment Flow
Developer pushes code → GitHub Actions triggers.

Workflow builds Spring Boot image → pushes to Docker Hub.

Workflow connects to remote server via SSH.

Compose file is generated with secrets → docker-compose up -d runs stack.

Your app + MySQL + MongoDB are live on the server.

With this setup, you now have CI/CD with GitHub Actions + Docker Compose + remote deployment via SSH — a production‑grade pipeline.

for MongoDb I have created New docker container And for Our Spring Boot App And MYSQL I have created one container for it how to used docker compose for these tools ?
Got it — since you already have two containers running (one for Spring Boot + MySQL together, and one for MongoDB), you can still orchestrate them cleanly with Docker Compose. The idea is to describe both services in a single docker-compose.yml so they run on the same network and can talk to each other.

📝 Example docker-compose.yml

version: "3.9"

services:
  springboot-mysql:
    image: your-dockerhub-username/springboot-mysql:latest
    container_name: springboot-mysql
    ports:
      - "8080:8080"
      - "3306:3306"   # expose MySQL if needed externally
    environment:
      SPRING_DATASOURCE_URL: jdbc:mysql://localhost:3306/mydb
      SPRING_DATASOURCE_USERNAME: root
      SPRING_DATASOURCE_PASSWORD: root
    restart: unless-stopped
    networks:
      - backend

  mongo:
    image: mongo:6
    container_name: mongo-db
    ports:
      - "27017:27017"
    environment:
      MONGO_INITDB_DATABASE: mydb
    volumes:
      - mongo_data:/data/db
    restart: unless-stopped
    networks:
      - backend

volumes:
  mongo_data:

networks:
  backend:
    driver: bridge





Key Notes
Spring Boot + MySQL in one container:

If you’ve baked MySQL into the same image as Spring Boot, you just run that container as springboot-mysql.

The app connects to MySQL via localhost:3306 inside that container.

MongoDB separate container:

Runs independently, but on the same backend network.

Your Spring Boot app can connect to it using mongodb://mongo:27017/mydb (since Compose gives the service name mongo as a hostname).

Networking:

Both services share the backend network, so they can resolve each other by service name.

You don’t need to expose MySQL externally unless you want to connect from outside.


How to Run
Save the file as docker-compose.yml.

Run:

docker-compose up -d

Access your app at http://localhost:8080.

MongoDB is available at localhost:27017 externally, or mongo:27017 internally from the Spring Boot container.

This way, Compose orchestrates your Spring Boot + MySQL combo container and your MongoDB container together, with networking and persistence handled automatically.
